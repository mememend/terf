# Циферки — Telegram Mini App

Мобильная веб-игра: игрок выпускает виртуальные SIM-карты, получает случайные игровые
номера разной редкости, собирает коллекцию, зарабатывает игровую валюту и повышает уровень.

**Номера — исключительно игровые предметы.** Все номера синтетические, генерируются на сервере
и не связаны с реальными абонентами. Базы реальных телефонных номеров, чужие контакты и
SMS-активации не подключаются. Символ `₽` обозначает внутриигровой баланс, не реальные деньги.

---

## Состав

| Часть | Что делает | Состояние |
|---|---|---|
| `shared/` | Игровое ядро: конфиг, анализатор узоров, генератор номеров, движок | готово |
| `frontend/` | React + TypeScript + Vite, интерфейс Mini App | готово |
| `backend/` | Node + Express + PostgreSQL, серверная логика, проверка Telegram | готово |
| `bot/` | Telegram-бот: запуск Mini App, команды, кнопка меню, реферальные ссылки | готово |
| админка | Панель параметров поверх серверного API, внутри Mini App | готово |

Одно ядро на клиент и сервер: `shared/` импортируют оба. Поэтому витрина «Шансы»
и фактическое выпадение физически не могут разойтись — это один и тот же код.

## Быстрый старт

```bash
npm install

# 1. Игровое ядро: проверка правил
npm run selftest

# 2. Типы всех трёх частей
npm run typecheck

# 3. Сервер API (без базы — поднимется хранилище в памяти)
cd backend
NODE_ENV=development ALLOW_DEV_AUTH=1 BOT_TOKEN=dev-token ADMIN_TELEGRAM_IDS=100001 \
  DATABASE_URL= npm run dev

# 4. Интерфейс (в другом окне)
npm run dev
# → http://127.0.0.1:5173

# 5. Бот (в третьем окне, нужен настоящий BOT_TOKEN)
BOT_TOKEN=<токен от @BotFather> WEBAPP_URL=https://ваш-адрес \
  BACKEND_URL=http://127.0.0.1:8080 BOT_INTERNAL_SECRET=<секрет> \
  npm run dev:bot
```

`frontend/.env.development` уже содержит `VITE_DEV_USER=100001`, поэтому в режиме
разработки вход выполняется без Telegram. Заголовок `X-Dev-User` сервер принимает
**только** при `ALLOW_DEV_AUTH=1` и вне продакшена.

### С PostgreSQL

```bash
cp .env.example .env      # заполнить DATABASE_URL и BOT_TOKEN

npm --workspace backend run migrate    # применить схему
npm run dev:api                        # сервер с постоянным хранением
```

Для продакшена `env.ts` намеренно падает на старте, если не заданы `BOT_TOKEN`
или `DATABASE_URL`: лучше не подняться, чем тихо работать без проверки подписи
или терять прогресс.

## Проверки

```bash
npm run selftest                        # правила игры и бот
npm run smoke                           # сквозная проверка API, хранилище в памяти
npm run test:pg                         # то же на настоящем PostgreSQL (PGlite)
npm run typecheck                       # типы shared, frontend, backend, bot
npm --workspace bot run build           # сборка бота
```

`selftest` прогоняет два набора. Первый — правила игры: опорный случай референса
(«65432» = 35 очков = Необычный), гашение пересекающихся узоров, сумму вероятностей
ровно 100 % для всех тарифов с удачей и без, попадание генератора в категорию,
сборку маски номера. Второй — бот: разбор команд, сборку клавиатур, обработку
нажатий и **живой запуск процесса бота** против локального эмулятора Bot API
с настоящим длинным опросом.

`smoke` поднимает собранный сервер на свободном порту и проверяет 55 утверждений,
в том числе идемпотентность выпуска, серверный расчёт категории и цены, право
владения при продаже, права администратора, влияние админ-панели на выпуск
и ограничение частоты.

`test:pg` поднимает **настоящий PostgreSQL** (PGlite — PostgreSQL 18.3, собранный
в WebAssembly, с сокет-сервером по проволочному протоколу) и прогоняет против него
тот же набор проверок обычным драйвером `pg`. Затем перезапускает приложение при
живой базе и убеждается, что коллекция и баланс сохранились, а состав совпадает
по идентификаторам. Так проверяются реальные SQL, транзакции и блокировка строки,
а не заглушка.

Инструкция по публикации — [docs/DEPLOY.md](docs/DEPLOY.md): база, systemd, nginx
с HTTPS, настройка бота и чек-лист перед открытием.

Бесплатные варианты размещения — [docs/FREE-HOSTING.md](docs/FREE-HOSTING.md):
туннель без регистраций для проверки в Telegram за десять минут и постоянный
бесплатный стек из Cloudflare Pages, Render и Neon.

## API

Все игровые маршруты требуют подписи Telegram в заголовке `X-Telegram-Init-Data`.
Сервер проверяет её сам и определяет игрока: клиент не может назваться другим.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | живость сервера и используемый драйвер хранилища |
| `GET` | `/api/state` | полное состояние игрока в форме `GameState` |
| `GET` | `/api/chances` | распределение категорий с учётом активной удачи |
| `POST` | `/api/release` | выпуск SIM: `{ tariffId?, countryId?, releaseId }` |
| `POST` | `/api/select` | выбор тарифа и региона, валюту не списывает |
| `POST` | `/api/sell` | продажа номера |
| `POST` | `/api/primary` | назначить номер основным |
| `GET` | `/api/digit/forecast` | прогноз замены цифры |
| `POST` | `/api/digit` | замена цифры за игровую валюту |
| `GET` | `/api/upgrades` | витрина улучшений: что можно сделать с номером и сколько стоит |
| `POST` | `/api/upgrade` | применить улучшение: `{ numberId, id, index?, a?, b? }` |
| `POST` | `/api/daily` | награда дня |
| `POST` | `/api/bailout` | бонус при балансе ниже стоимости Стандарта |
| `GET` | `/api/meta` | тарифы и параметры для экрана правил |
| `GET` | `/api/admin/config` | параметры игры и переопределения из панели |
| `PUT` | `/api/admin/config` | изменить параметр с проверкой значения |
| `GET` | `/api/admin/config` | базовые значения, переопределения и то, что действует сейчас |
| `PUT` | `/api/admin/config` | изменить параметр с проверкой значения |
| `DELETE` | `/api/admin/config/:key` | снять переопределение — вернуть базовое значение |
| `GET` | `/api/admin/stats` | статистика выпусков |
| `GET` | `/api/admin/audit` | журнал ошибок и действий администраторов |
| `POST` | `/internal/profile` | сводка профиля для бота, отдельный секрет `X-Bot-Secret` |

`GET /api/state` дополнительно отдаёт `isAdmin` — по нему клиент решает, показывать ли
раздел. Это только витрина: каждый админ-запрос всё равно проверяет права заново.

## Админ-панель

Открывается из бокового меню и видна только администратору. Шесть разделов:
тарифы (цена и распределение категорий), очки за узоры, спрос регионов, базовые
цены категорий, статистика и журнал действий.

**Правки действуют немедленно.** Переопределения хранятся в таблице `game_config`,
применяются к общему конфигу при старте и после каждой записи — без перезапуска
сервера. Это проверено сквозным тестом: цена Премиума меняется на 12 345, выпуск
списывает ровно 12 345; вероятности Стандарта меняются — витрина шансов
пересчитывается и по-прежнему суммируется в 100 %.

**Базовое значение не теряется.** Перед наложением переопределений конфиг
возвращается к снимку базовых значений, поэтому снятие переопределения
восстанавливает исходное число, а повторное применение всегда даёт один результат.
Панель показывает и действующее значение, и зачёркнутое базовое.

**Проверка значений на сервере.** Реестр допустимых ключей: `tariff.<id>.price`,
`tariff.<id>.odds`, `pattern.<id>`, `region.<id>`, `rarity.<id>.basePrice`. Всё
остальное отклоняется. Сумма вероятностей обязана быть ровно 100 %, цена — целым
положительным числом, спрос — в пределах от 0 до 10. Пояснение отказа приходит
на клиент и показывается игроку, а не глушится общим «ошибка сервера».

## Бот

Отдельный процесс, общается с Telegram длинным опросом. Внешних зависимостей нет —
клиент Bot API написан поверх `fetch`.

**Команды:** `/start` (с реферальным параметром `ref_<id>`), `/play`, `/chances`,
`/rules`, `/profile`, `/share`, `/help`.

**Кнопка меню** выставляется при старте и открывает Mini App прямо из поля ввода —
это постоянный вход в игру, независимый от истории чата. Кнопка `web_app` в
сообщениях открывает приложение внутри Telegram, без перехода в браузер.

**Реферальные ссылки** собираются через `t.me/<bot>?startapp=ref_<id>` и уходят
в кнопку «Поделиться».

**Аутентификация бота к серверу** — общий секрет `BOT_INTERNAL_SECRET` в заголовке
`X-Bot-Secret`, сравнение постоянного времени. Если секрет не задан, внутренние
маршруты не поднимаются вовсе. Профиль незнакомца не создаётся: написать боту
в чат — ещё не значит начать играть.

**Устойчивость опроса.** Смещение `update_id` продвигается только после успешной
обработки, одно сломанное обновление не роняет цикл. При сбоях пауза растёт
экспоненциально; при `409 Conflict` (второй экземпляр с тем же токеном) —
увеличивается дополнительно, чтобы не забивать Telegram запросами.

## Как устроена защита

**Подпись Telegram.** `initData` проверяется по алгоритму из документации:
секрет = `HMAC_SHA256("WebAppData", bot_token)`, подпись = `HMAC_SHA256(секрет, data_check_string)`.
Сравнение — постоянное по времени. Подпись старше суток отклоняется.
До проверки всё, что клиент сообщил о себе, считается недоверенным.

**Права администратора** определяются только по `ADMIN_TELEGRAM_IDS` после проверки
подписи. Ни `username`, ни любое поле из тела запроса на это не влияют.

**Идемпотентность выпуска.** Три уровня:
1. `release_id` — первичный ключ таблицы `releases`, повтор отсекается схемой БД;
2. предварительная проверка `release_id` до запуска движка;
3. проверка `processedReleaseIds` внутри движка, уже под блокировкой строки игрока.

**Баланс.** Все операции игрока идут через `SELECT ... FOR UPDATE` по строке игрока,
поэтому одновременные запросы встают в очередь и не могут списать валюту дважды.
Дополнительно на таблице стоит `CHECK (balance >= 0)`.

**Результат выпуска** определяет только сервер. Клиент присылает намерение
(тариф, регион), а не результат. Категория предмета берётся из фактических очков узора.

**Ограничение частоты** — корзина токенов на игрока, защищает от флуда выпусками.

## Что уже работает

**Главный экран** — верхняя панель с уровнем и балансом, большая SIM-карта с подчёркнутыми
цифрами узора и цветом категории, баннер и индикатор удачи с таймером, переключатели
роуминга и тарифа, широкая кнопка выпуска.

**Модальные окна** — тариф (карусель четырёх карточек, доля «редкий и выше», таблица
вероятностей), роуминг (сетка 3 колонки, 10 регионов, «Свои номера», поиск),
шансы (шесть категорий с процентами и «1 из N»), замена цифры с прогнозом цены.

**Экраны** — коллекция со сводкой, сортировкой, фильтрами по регионам и категориям
и поиском по цифрам; карточка номера с разбором «Почему …» по узорам и очками;
мастерская улучшений; история; профиль; задания с достижениями; рейтинг; магазин;
правила; настройки.

**Регионы** — 25 стран с флагами, кодами, масками номеров, спросом и пулом синтетических
операторов: Россия, США, Великобритания, Германия, Франция, Финляндия, Япония, ОАЭ,
Казахстан, Бразилия, Турция, Испания, Италия, Польша, Китай, Индия, Южная Корея, Канада,
Австралия, Мексика, Нидерланды, Швеция, Швейцария, Португалия, Чехия.

**Оператор всегда подтверждается префиксом.** Номер не приписывается бренду без оснований:
если сгенерированный префикс ничей, генератор пробует подставить префикс настоящего
оператора региона и принимает подстановку, только если категория сохранилась. Если и это
невозможно — номер уходит нейтральному перевозчику `Carrier`. Так обычные номера выглядят
как настоящие (`+7 920` → Гигафон, `+81 80` → Sakura, `+41 79` → Helvetia), а красивые
вроде `7777777777` честно остаются без бренда, потому что их красота — в целой строке.

**Коллекция** — переключатель «сеткой / по регионам»: во втором режиме номера сгруппированы
по странам с заголовком, количеством и суммарной стоимостью группы.

**Профиль** — карточка игрока с круговым индикатором уровня, полоса опыта, четыре плитки
со сводкой и разбивка коллекции по категориям с полосками доли.

**Задания** — карточка награды дня с полосой серии из семи точек и сетка достижений
с прогрессом и наградой.

**Рейтинг** — место игрока с пьедесталом первых трёх, подсветкой своей строки и полным
списком остальных.

**Магазин** — карточки разделов (бонус баланса подсвечивается, когда доступен, остальные
честно помечены как «скоро»), тарифы теми же цветными плашками, что в карусели, и сетка
из 25 регионов со спросом.

**Причина вместо запрета.** Если выпуск недоступен, кнопка не просто гаснет — под ней
появляется строка с точной суммой, которой не хватает, и переходом к смене тарифа.

## Мастерская: как номер может улучшиться

Пять способов сделать номер дороже. Они разные не только ценой, но и характером —
это и есть ответ на вопрос «как номер может улучшиться».

| Способ | Цена | Что делает | Случайность |
|---|---|---|---|
| **Замена цифры** | 500 ₽ | одна цифра меняется на случайную | есть, с прогнозом |
| **Перестановка** | 900 ₽ | две цифры меняются местами | нет — результат виден заранее |
| **Смена оператора** | 2 500 ₽ | номер переходит к другому оператору региона | нет — результат виден заранее |
| **Перебор** | 5 000 ₽ | все цифры подбираются заново внутри категории | есть, в границах категории |
| **Апелляция** | 50 % базовой цены следующей категории | категория поднимается на ступень | нет — гарантированно |

**Перестановка и смена оператора показывают будущее.** Прямо в окне считается тот же
расчёт, что и на сервере: новые очки, новая категория, новая цена и разница в рублях.
Игрок видит, что получится, до оплаты — и сам решает, стоит ли.

**Смена оператора меняет только префикс.** Номер переезжает к другому оператору того же
региона: префикс подменяется, остальные цифры остаются на месте. Выбрать можно любого
оператора региона, кроме текущего, а оператора чужого региона сервер отклонит — номер
не должен терять прописку.

**Недопустимые перестановки отклоняются.** Номер не может начинаться с нуля, поэтому
перестановка, ставящая ноль в первую позицию, запрещена — и на сервере, и в витрине
(такие позиции в интерфейсе просто неактивны). Обмен одинаковых цифр тоже отклоняется:
это была бы оплата ни за что.

**Категория всегда из очков.** После любой операции категория, множитель и цена
пересчитываются заново тем же анализатором. Операция может и понизить категорию —
это честно, и предпросмотр предупреждает об этом заранее.

**Апелляция упирается в предел.** У мифического номера подниматься некуда, и операция
честно помечена как недоступная вместо того, чтобы брать деньги впустую.

**Сервер** — проверка подписи Telegram, постоянное хранение, серверная генерация,
идемпотентность, защита баланса, ограничение частоты, админ-панель параметров.

**Бот** — запуск Mini App кнопкой в сообщении и кнопкой меню у поля ввода,
команды со справкой и шансами, профиль игрока прямо в чате, реферальные ссылки.

**Админ-панель** — шесть разделов с правкой цен, вероятностей, очков за узоры,
спроса регионов и базовых цен категорий; статистика выпусков и журнал действий.
Каждое изменение проверяется сервером и действует немедленно.

**Два режима интерфейса** — с сервером (боевой) и локально на `localStorage`
(демо и офлайн). Экраны разницы не видят.

**Движение** — сцена выпадения собирается по ступеням: вспышка, карточка, категория,
оценка. Чем выше категория, тем богаче сцена — у обычного только вспышка, у эпического
и выше включаются вращающиеся лучи, у мифического разлетается 36 искр. Карточка дрожит
тем сильнее, чем выше готовящаяся категория, а рука получает толчок соответствующей силы.

Дальше по мелочи: баланс доезжает до нового значения и подчёркивает изменение,
цифры номера встают по очереди, карточки коллекции проявляются волной, редкие номера
дышат свечением, экраны въезжают при переходе, при запуске показывается заставка
вместо пустого экрана. Всё уважает системную настройку `prefers-reduced-motion`.

## Требования к числам — ждут согласования

Все игровые параметры лежат в одном файле — `shared/src/config.ts`.
Значения сняты с референсов и **являются предложением**, а не финальным балансом.

| Параметр | Текущее значение | Статус |
|---|---|---|
| Цены тарифов | Стандарт 1 700 ₽, Плюс 7 000 ₽, Премиум 34 500 ₽, Элит — по билету | Плюс и Элит требуют подтверждения |
| Вероятности | по 6 категориям для каждого тарифа, сумма 100 % | согласовать |
| Базовые цены категорий | 1 500 / 3 200 / 14 000 / 75 000 / 520 000 / 4 000 000 ₽ | предложение |
| Множитель узора | `1 + очки / 60` | предложение |
| Границы очков | 9 / 39 / 79 / 139 / 219 / 220+ | опорная точка: «65432» = 35 очков = Необычный |
| Очки за узоры | от 7 за цифру лесенки до 300 за полное повторение | предложение |
| Спрос регионов | 0,70 (Бразилия) … 1,40 (ОАЭ) | предложение |
| Стартовый баланс | 99 800 ₽ | с референса |
| Опыт за уровень | `250 + (уровень − 1) × 120` | предложение |
| Награда дня | `700 + серия × 150` | предложение |

**Открытые вопросы:**
1. Цена тарифа **Плюс** и что такое **«по билету»** у Элита: билет покупается за игровую
   валюту, падает из рулетки или выдаётся по уровню?
2. Категория по очкам и ролл по вероятностям — оставляем связку «ролл задаёт цель,
   очки подтверждают категорию», или категорию считаем только по очкам?

Менять числа можно и через админ-панель: `PUT /api/admin/config` принимает ключи вида
`tariff.<id>.price`, `tariff.<id>.odds`, `pattern.<id>`, `region.<id>` и проверяет
значение до записи (сумма вероятностей обязана быть ровно 100 %).

## Соответствие референсам

Снято точно: композиция главного экрана, оформление четырёх тарифов с цветными полосами,
сетка роуминга, окно «Шансы» с шестью категориями, список 15 узоров, разбор «Почему Необычный»
с очками, экран замены цифры с прогнозом, структура коллекции и карточки номера.

Предложено самостоятельно: базовые цены категорий, множитель узора, сопряжение очков,
спрос регионов, награда дня, формула опыта, экраны, которых не было в референсах
(история, профиль, задания, рейтинг, магазин, правила, настройки).

Три расхождения с референсом, исправленные намеренно:
1. В референсе при активной удаче сумма показанных вероятностей превышает 100 %.
   Здесь распределение после удачи нормализуется к ровно 100 %.
2. Категория предмета всегда берётся из фактических очков узора, а не из запроса клиента.
3. Узоры, описывающие один рисунок, не суммируются: пары гасят серию, палиндром гасит
   зеркало, чередование гасит повтор блока.
